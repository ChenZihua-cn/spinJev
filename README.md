# spinJev

JEV 风格的**具身智能体脊髓模型**：把机器人控制回路里那些高频、低维、可类型化的判断，从大模型手里卸载给一个又快又便宜、并且**知道自己有多确定**的小决策模型。

> 状态：环境验证已完成（`test/`），仿真代码尚未开始。路线图见 [PLAN.md](PLAN.md)。

---

## 缘起：Jev 是什么

**Jev** 是 TypeSafe AI 于 2026-09-15 发布的首个「System One 模型」，由前 OpenAI 研究员、RLHF 联合发明者 Diogo Almeida 与 Erik Gafni、Sasha Sheng 创立，同日披露 DCVC 领投的 4000 万美元种子轮。名字致敬经济学家 William Stanley Jevons——暗合**杰文斯悖论**：当决策成本大幅下降，它的使用场景会爆炸式增长。

给它一个 `state`（任意嵌套 JSON 或字符串）加一组类型化问题，它直接返回**带校准概率**的答案。三种问题原语：

| 原语 | 语义 | 输出 |
|---|---|---|
| **Noul** | 是/否判断 | 0–1 的概率 |
| **Choice** | 多选分类 | 选项 + 概率（上限 255 项） |
| **Score** | 量表打分 | 序数评分 + 置信度 |

调用方根据阈值决定「自动执行」还是「升级处理」。官方口径：端到端延迟 70–500 ms，输入 \$0.042/百万 token，输出免费；渠道有 OpenRouter（`typesafe/jev-1.13`）、Vercel AI Gateway、Cloudflare Workers AI，上下文 32K。

### 与 LLM 的五点区别

1. **非自回归 vs 自回归**——Jev 单次并行采样，对同一 state 的所有问题并行求值，一次输出整个答案分布，没有逐 token 生成。这是架构层面快的根本原因。
2. **RLCD vs RLHF**——训练目标不是「人类更喜欢」，而是**概率与真实结果匹配**：报 90% 置信度的判断，长期就应约 90% 正确。
3. **类型化决策 vs 自由文本**——输出必在预定义答案空间内，schema 错误「数学上不可能」，幻觉在结构上被消除（但选错选项仍会发生）。
4. **互补而非替代**——Jev 不写字、不写代码、不解释推理。合理架构是「Jev 决策 + LLM 写作」。
5. **量级差异**——官方基准称单次决策约 \$0.000081 / 0.114 s，对比 LLM 的 \$0.01388 / 8.566 s。这是厂商高限估计；第三方实测中 Vercel 换掉 OpenAI 分类器后快 5–18 倍且准确率更高，Bryo AI 对比 Gemini 则是成本降 10–20 倍、准确率略低。

**一句话**：LLM 是「会聊天、会写作的推理引擎」，Jev 是「只会做选择题但做得极快、极便宜、且知道自己有多确定」的决策函数。

## 核心命题：决策空间被错误地放大了

Agent 的推理循环里，绝大多数「决策」其实是低维、高频、可类型化的，却被迫用一次完整的 LLM 调用完成：

| 判断类型 | 例子 | 本质 | 谁该做 |
|---|---|---|---|
| 开放推理 | 「这个 bug 的根因是什么」 | 无边界、需联想 | 大脑（LLM） |
| 受限选择 | 报错后重试 / 换工具 / 升级人工 | 有限选项集 | 小脑（Jev） |
| 确定性逻辑 | 参数格式转换、重试计数 | 规则即可 | 脊髓（纯代码） |

报错处理尤其典型：看起来需要「理解错误」，但拆解后 90% 的错误模式是已知的——超时→重试、权限错误→换凭证、依赖缺失→装包。让 LLM 每次重新读懂整个 traceback 是巨大浪费；一次 `Choice` 并行求值就能给出带置信度的路由。

## 三层架构

```
┌─────────────────────────────────────────┐
│  大脑（LLM，慢、贵、开放推理）            │
│  规划 / 根因分析 / 创造性方案 / 最终裁决    │
│  触发条件：小脑置信度 < τ，或问题无法类型化 │
└──────────────▲──────────────────────────┘
               │ escalate（带 Jev 的概率分布 + 原始状态）
┌──────────────┴──────────────────────────┐
│  小脑（Jev，快、便宜、并行）              │
│  Choice：错误路由、工具选择、状态分类      │
│  Noul：  该不该现在打断规划？条件满足了吗？ │
│  Score： 当前进展健康度、retry 价值评估    │
└──────────────▲──────────────────────────┘
               │ state = 结构化观测（不是原始日志）
┌──────────────┴──────────────────────────┐
│  脊髓（纯代码，确定性）                   │
│  重试计数、超时控制、schema 校验、幂等      │
└─────────────────────────────────────────┘
```

三个关键机制：

1. **状态工程，而不是提示工程。** 喂给小脑的不是原始信号全文，而是预处理过的结构化观测（错误类型标签、重试次数、路径深度、近几步决策序列）。确定性手段能解决的（正则、返回码）先解决，剩下的模糊部分才交给 Jev。
2. **置信度分层路由。** `P > 0.9` 自动执行，大脑根本不知道发生过；`0.6 < P < 0.9` 执行但记入审计日志，大脑下轮规划能看到「小脑做过 N 次低置信度决策」；`P < 0.6` **升级**——payload 很小，不是「请重新理解整个环境」，而是「小脑在重试/换工具/放弃之间拿不准（0.4/0.35/0.25），你来推理」。大脑只在真正的歧义点上工作。

   > **具身场景要把这套阈值语义倒过来。** 软件 agent 里 70% 置信度选错只是多花一轮；机器人里 70% 置信度对应的动作可能撞人。安全关键层的默认不该是「置信度高就自动执行」，而是「**除非置信度压倒性高，否则一律走慢路径**」。校准在这里不是评测指标，是安全属性。
3. **分工原则：能用 Choice 表达的判断绝不上大脑。** 大脑**产出**计划，小脑**监督执行**。大脑低频介入（每 N 步或异常时），小脑每步高频运行。决策变便宜之后，你反而敢在每一步都做判断——这就是杰文斯悖论的正向用法。

## 为什么落到具身智能

具身场景可能比软件 agent **更适合**这套架构，因为生物就是这样演化出来的：运动控制太高频、太危险，等皮层「想清楚」早就摔倒了。

最贴切的隐喻是**膝跳反射**：叩击髌韧带 → 感受器 → 传入神经 → 脊髓灰质整合 → 传出神经 → 效应器 → 小腿抬起。全程**不走大脑**，毫秒级完成，且反射强度随牵张程度连续变化——它本身就是一条「可校准的反射」。

```
叩击(刺激) → 感受器 → 传入神经 ──┐
                                 ├→ 脊髓(灰质整合) → 传出神经 → 效应器(动作)
              大脑 ←── 上行通报(事后才知道) ─┘
```

具身智能里的对应物：高频本体感觉 → 低层策略 → 动作原语；而「大脑」（LLM/VLA）只在慢时间尺度上接管新任务，且通常**事后**才被通报，而不是每一步都参与。

软件 agent 的决策频率是秒级，机器人控制环是 **kHz 级**。力矩、IMU、触觉阵列、关节编码器每秒涌进成千上万维信号，而其中真正的「决策点」（要不要重新抓握、这条腿要不要触发步态修正、这个接触是预期内碰撞还是障碍）是**稀疏且可类型化**的。当前主流做法把原始信号序列一股脑塞进 VLA 模型（RT-2、π0）端到端学——那等于让教授每秒做一万次条件反射。合理切分是按时间尺度分层：

| 层 | 频率 | 职责 | 实现 |
|---|---|---|---|
| 脊髓 | ~1 kHz | 力矩环、平衡 reflex、急停 | 纯控制论，不学习或极慢学习 |
| 小脑 | 10–100 Hz | 步态相位切换、抓握策略选择、跌倒风险 Noul、操作成功度 Score | 类型化决策模型 |
| 大脑 | 0.1–1 Hz | 「这个杯子打滑了，换目标还是调整姿势」 | LLM，只看小脑压缩后的状态摘要 |

**一个具体的化学反应**：触觉打滑检测。皮肤阵列 200 Hz 信号进脊髓做滤波与特征提取（接触力变化率的滑移模式），小脑的 Noul 给出「是否打滑 P=0.94」且置信校准——94% 的情况下直接触发抓握力重分配 reflex，**皮层完全不参与**，延迟从「拍图 + 大模型推理 500 ms」变成 5 ms。

这也改变了成本结构：高频决策被卸载后，大脑可以只配一个本地小开源模型。

### 「脊柱神经」数据总线

这是最容易被低估的一层，也是 ROS/ROS2 生态没做好的部分。主张是**总线必须分频、分级、事件溯源**：

1. **物理层照搬生物，两类传入神经。** 本体感觉（关节角、力矩、IMU）走高频裸通道，脊髓自己消费；外源感觉（相机、深度、语言指令）低频进皮层。不要让所有信号共享一个 topic 队列——生物脊髓只做局部反射，视觉信号根本不会每毫秒打扰它。
2. **中间需要「脊髓灰质」：环形缓冲 + 特征压缩机。** 原始信号先进固定长度 ring buffer（如 2 s 滑窗），轻量编码器（甚至就是滑动统计量 + 小型时序编码器）把窗口压成嵌套 JSON：`{接触状态, 滑移指数, 关节裕度, 近2s异常事件列表}`。**这才是喂给小脑 `state` 的东西**——小脑从不看原始波形。
3. **下行通路带「皮层门控」。** 生物里脊髓 reflex 可被大脑抑制（踩到钉子还能走完那一步再叫）。每条下行命令标权重：脊髓级（急停）不可否决；小脑级（步态修正）可被大脑以低置信度为由否决；大脑级（重新规划路径）可被小脑以安全护栏否决。置信度在这里不只是路由信号，还扮演**神经调质**的角色。
4. **安全约束留在硬件层，别学习。** 工作空间限制、力矩上限、碰撞急停应是总线上的确定性旁路（hardwired interlock），任何学习组件都无权绕过。**脊髓不能删。** 同理，小脑 `Choice` 的候选集必须**先由代码做物理预过滤**（碰撞、关节限位、可达性），模型只在合法候选里挑——漏掉这一步，非自回归输出「零越界」的优势就只剩形式上的了。
5. **事件溯源日志作为共同记忆。** 所有决策事件（state 快照 + 小脑判断 + 置信度 + 结果）落盘。这是可学习性的基础设施。

### 冻结权重的可学习性

大脑和小脑主干权重都冻结，系统怎么进步？生物的答案是：**可塑性是局部的、受门控的、以记忆回放为载体的。**

1. **小脑的学习 = 大脑裁决的蒸馏**（最优雅的回路）。每次低置信度升级，大脑给出最终决策——这就是一个**免费的标注样本** `(state, 大脑的选择)`。积累一批后用类 RLCD 的校准强化学习微调小脑（LoRA adapter 形式，主干冻结）。效果是**升级率随时间单调下降**，小脑把大脑的判断内化成反射。这正是生物小脑监督学习（爬行纤维教学信号）的机器对应物。校准目标不变：新学的判断仍输出置信度、仍可被否决。
2. **大脑的学习 = 小脑失败案例的回放。** 从事件日志筛两类高价值样本：小脑**高置信度但结果失败**的（过自信盲区）、小脑低置信度升级后**大脑也答错**的（真正的 OOD）。大脑因此在学的不是动作，是**仲裁能力**——分辨哪些该反射、哪些真该思考。
3. **用世界模型离线演练，而不是真机试错。** 在 MuJoCo/Isaac 里跑小脑策略 + 简单大脑，用域随机化生成海量 `(state, decision, outcome)` 三元组，离线 RL 或校准回归更新 adapter。sim2real gap 由「低置信度升级」兜底——**不自信的反射天然保守**，这是冻结系统比端到端 VLA 更安全的性质。
4. **学习要门控：不是每个错误都更新。** 生物可塑性受神经调质门控；对应过来，只有**意外性**（prediction error）足够大且**事件重要性**（跌倒风险、任务失败）足够高时才触发写入，否则系统在噪声里漂移。工程上：事件日志 → 惊讶度打分 → 只把 top-k 意外事件送进学习管线。无差别的梯度更新会让系统平庸化，**选择性可塑性 > 持续可塑性**。

### 闭环

大脑教小脑（蒸馏仲裁）→ 小脑给大脑减负（卸载反射）→ 脊柱给两者提供共同语言（类型化状态总线）→ 事件日志让双方各自从对方的成功与失败中学习，而主干权重保持冻结，可塑性被约束在 adapter、记忆回放和门控写入里。

比端到端大模型路线慢热，但每一步都**可审计、可校准、可安全验证**。

## 参照实现：这条路有人走通过一半，但只走了一半

两个开源复现把官方 Jev 的黑箱摊开了，各自验证了这套架构的一半。本项目的做法是**拆开两边各取一半**。

### NanoJev：验证了「问题设定」与「代码拥有工作流」

**NanoJev**（MIT，权重与数据全开源）是目前最完整的 Jev 复现——模型 + 数据集 + 训练管线 + 持久推理服务 + 可交互演示一条龙。

```
state + question + candidates
        │
        ▼
   Qwen3-0.6B 骨干        ← 单次前向，零输出 token 解码
        │                    多个 state/question/候选路径同批并行
        ▼
   共享决策头
     · Choice：集合注意力 + softmax → 2–255 个候选的分布
     · Boolean：sigmoid → 命题成立概率
     · Score：2–10 个有序等级的分布 + 概率加权期望
        ▼
   每个候选：类型化值 + 归一化概率
```

- 骨干只用 **Qwen3-0.6B**；实测例子是 6 个状态、18 个问题、44 条候选路径在**一次前向**中全部解算。
- Choice 候选集**动态**（2–255），共享评分头 + 集合注意力并行打分后 softmax；Boolean 走 sigmoid；Score 输出等级分布与期望。
- 没有「投影到词表再逐 token 解码」这一步 → 输出直接是序列化的概率张量，从原理上排除解析错误与 schema 越界。
- 单 checkpoint 跨 4 个游戏任务复用（ViZDoom Basic / Predict Position / 50×50 迷宫 / 贪吃蛇）；常驻显存约 2.4 GB（FP32），消费级显卡可训可跑。

**最值得抄的是它的系统哲学：代码拥有工作流。** 模型只做模糊的语义判断层，记忆、规划、安全约束全在确定性代码里：

| 任务 | 代码负责 | 模型负责 | 结果 |
|---|---|---|---|
| 50×50 迷宫 | 记撞墙历史、探索未走过的边、沿已验证路径回溯重定位 | 只判断四个局部方向的安全性 | 225 次到达终点；对照原版 Jev API 需 **2738** 次 |
| 贪吃蛇 | 常规规划器过滤立即碰撞动作、找出通往食物的静态路径 | 只在幸存动作之间**打破平局** | 吃到 27 个食物仍存活 |

这正是本文「脊髓不能删」的独立验证：**模型是模糊判断层，不是整个程序。** 配套 **JevHarness** 子项目让 LLM 自动编写任务专用的决策 harness。

### Laya：验证了「训练方法」与「安全出口」

**Laya**（ModernBERT-large 双向编码器路线，421M）走的是不同的架构赌注，自报了更好的校准指标。对本项目真正有价值的是它的两个贡献：

- **RLCD 闭式更新**：不需要 PPO 的在线采样，按 `π* ∝ π_ref · exp(r/β)` 做指数倾斜迭代。对机器人这种「数据贵且离线」的样本特别友好。
- **act-or-escalate 头**：一个专门的「该自己拍板还是上报」的校准二值头。机器人脊柱最需要的安全性质就是**知道什么时候不该自己拍板**——分布熵高就 escalate 给大脑，正好对应反射弧里「脊髓搞不定才上报」的逻辑。

### 借什么，不借什么

| 来源 | 借 | 不借 | 理由 |
|---|---|---|---|
| **Laya** | RLCD 闭式更新；act-or-escalate 头 | ModernBERT 文本骨干 | 文本编码器吃不了关节角、IMU、深度图 |
| **NanoJev** | 环境闭环的序贯决策设定；类型化决策头；代码拥有工作流 | 0.6B 解码器骨干 | 脊柱要在机载计算（Orin 级）跑到 50–100 Hz+，0.6B 太重 |

于是本项目的小脑是：**本体感觉小编码器（MLP / 1D-conv，~10–50M）+ 候选动作头 + act-or-escalate 头**，单次前向输出动作分布与 escalate 概率。

> 关键设计：**把动作空间离散成「原语 / 技能」而不是电机力矩。** 这和反射的层级一致——脊髓选的也是「伸腿」这个模式，不是逐个肌肉纤维。Jev 的 candidate-actions 设计在这里天然契合，这也是 Jev 系范式比 Laya 的纯文本分类更值得作骨架的原因。

### 与官方 Jev 的对应

| 维度 | 官方 Jev | NanoJev | Laya |
|---|---|---|---|
| 骨干 | 未公开 | Qwen3-0.6B | ModernBERT-large（421M） |
| 输出原语 | Choice / Score / Noul | Choice / Boolean / Score | 分类 + 校准 + act-or-escalate |
| 训练方法 | RLCD | 决策头监督训练 | RLCD 闭式 |
| 任务范围 | 通用类型化决策 API | 窄域游戏 | 窄域分类 |

### 诚实定位

- **这条路目前没人走通过。** 不管 Laya 还是 NanoJev，机器人上的数字都是零。本项目实际上是在做「第一个把 RLCD 决策头放上真机」的尝试，前两个月大概率连仿真都调不顺——这很正常，不是路线错了。
- **别把脊柱做成端到端大策略。** 那样它就成了一个小 VLA，失去「快、可校准、可接管」的全部意义。它的价值恰恰在于**窄而确定**——只负责几十种原语的选择和反射，不试图理解任务。
- NanoJev 的训练目标集中在游戏等窄任务上，**不能外推为通用决策能力**；它证明的是「0.6B + 类型化决策头这个架构成立」，不是「拿来做机器人就行」。
