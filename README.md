# spinJev

一个 Jev 风格的**具身智能体脊髓模型**：把机器人控制回路里那些高频、低维、可类型化的判断，从大模型手里卸载给一个又快又便宜、并且**知道自己有多确定**的小模型。

> 状态：阶段 1a 的代码已落地（本体资产、脊髓控制器、硬护栏、候选预过滤、任务层），验收**已通过**——`test/test_spine.py` 的 4 个固定点位 4/4 完成抓放；20 个随机可达点位上，真值位姿 17/20、单次含噪检测 12/20、悬停平均 20 帧 17/20、60 帧 19/20。阶段 1b 的总线、感知模拟器、专家与采集器也已能跑。决策模型尚未开始训练。路线与实测细节见 [PLAN.md](PLAN.md)。

## 缘起：Jev 是什么

**Jev** 是 TypeSafe AI 于 2026-09-15 发布的「System One 模型」，由前 OpenAI 研究员、RLHF 共同发明者之一 Diogo Almeida 与 Erik Gafni、Sasha Sheng 创立，同日披露 DCVC 领投的 4000 万美元种子轮。名字致敬经济学家 William Stanley Jevons——暗合**杰文斯悖论**：当决策成本大幅下降，它的使用场景会爆炸式增长。

给它一个 `state`（任意嵌套 JSON 或字符串）加一组类型化问题，它返回**带校准概率**的答案。三种问题原语：

| 原语 | 语义 | 输出 |
|---|---|---|
| **Noul** | 是/否判断 | 0–1 的概率 |
| **Choice** | 多选分类 | 选项 + 概率（上限 255 项） |
| **Score** | 量表打分 | 序数评分 + 置信度 |

调用方根据阈值决定「自动执行」还是「升级处理」。官方口径：端到端延迟 70–500 ms，输入 \$0.042/百万 token，输出免费；渠道有 OpenRouter（`typesafe/jev-1.13`）、Vercel AI Gateway 和 Cloudflare Workers AI，上下文 32K。

### 与 LLM 的区别

1. **非自回归 vs 自回归。** Jev 单次并行采样，对同一 state 的所有问题并行求值，一次输出整个答案分布，没有逐 token 生成。这是它快的根本原因。
2. **RLCD vs RLHF。** 训练目标不是「人类更喜欢」，而是**概率与真实结果匹配**：报 90% 置信度的判断，长期应约 90% 正确。
3. **类型化决策 vs 自由文本。** 输出必在预定义答案空间内。TypeSafe 称 schema 错误「数学上不可能」；准确的说法是**排除 schema 越界**，选错选项仍会发生。
4. **互补而非替代。** Jev 不写字、不写代码、不解释推理。合理架构是「Jev 决策 + LLM 写作」。
5. **量级差异。** 官方基准称单次决策约 \$0.000081 / 0.114 s，对比 LLM 的 \$0.01388 / 8.566 s——这是厂商高限估计。第三方实测中，Vercel 换掉 OpenAI 分类器后快 5–18 倍且准确率更高；Bryo AI 对比 Gemini 则是成本降 10–20 倍、准确率略低。

**一句话**：LLM 是「会聊天、会写作的推理引擎」，Jev 是「只会做选择题但做得极快、极便宜、且知道自己有多确定」的决策函数。

## 核心命题：决策空间被放大了

Agent 的推理循环里，大量「决策」其实是低维、高频、可类型化的，却各自花了一次完整的 LLM 调用：

| 判断类型 | 例子 | 本质 | 谁该做 |
|---|---|---|---|
| 开放推理 | 「这个 bug 的根因是什么」 | 无边界、需联想 | 大脑（LLM） |
| 受限选择 | 报错后重试 / 换工具 / 升级人工 | 有限选项集 | 小脑（Jev 式模型） |
| 确定性逻辑 | 参数格式转换、重试计数 | 规则即可 | 脊髓（纯代码） |

报错处理是典型：看起来需要「理解错误」，但多数常见错误能归进少数已知类别——超时、权限、依赖缺失。让 LLM 每次重新读整个 traceback 是浪费；一次 `Choice` 并行求值就能给出带置信度的路由。

## 三层架构

下面这张图是**软件 agent 里的形态**，换成机器人后各层职责会变（见下一节）：

```
┌─────────────────────────────────────────┐
│  大脑（LLM，慢、贵、开放推理）            │
│  规划 / 根因分析 / 创造性方案 / 最终裁决    │
│  触发条件：小脑置信度 < τ，或问题无法类型化 │
└──────────────▲──────────────────────────┘
               │ escalate（带概率分布 + 原始状态）
┌──────────────┴──────────────────────────┐
│  小脑（快、便宜、并行）                   │
│  Choice：错误路由、工具选择、状态分类      │
│  Noul：  该不该现在打断规划？条件满足了吗？ │
│  Score： 当前进展健康度、retry 价值评估    │
└──────────────▲──────────────────────────┘
               │ state = 结构化观测（不是原始日志）
┌──────────────┴──────────────────────────┐
│  脊髓（纯代码，确定性）                   │
│  重试计数、超时控制、schema 校验、幂等      │
└─────────────────────────────────────────┘
```

三个关键机制：

1. **状态工程，而不是提示工程。** 喂给小脑的不是原始信号全文，而是预处理过的结构化观测（错误类型标签、重试次数、路径深度、近几步决策序列）。确定性手段能解决的（正则、返回码）先解决，剩下的模糊部分才交给模型。

2. **置信度分层路由。** 以 `P > 0.9` 自动执行、`0.6 < P < 0.9` 执行并记审计日志、`P < 0.6` 升级为例——阈值要按任务调，不是定值。升级的 payload 很小，不是「请重新理解整个环境」，而是「小脑在重试/换工具/放弃之间拿不准（0.4/0.35/0.25），你来推理」。大脑只在真正的歧义点上工作。

   > **具身场景要把这套阈值语义倒过来。** 软件 agent 里 70% 置信度选错只是多花一轮；机器人里 70% 置信度对应的动作可能撞人。安全关键层的默认不该是「置信度高就自动执行」，而是「**除非置信度压倒性高，否则一律走慢路径**」。校准在这里不是评测指标，是安全属性。

3. **能用 Choice 表达的判断不上大脑。** 大脑**产出**计划，小脑**监督执行**。大脑低频介入（每 N 步或异常时），小脑每步高频运行。决策变便宜之后，你反而敢在每一步都做判断——这是杰文斯悖论的正向用法。

## 为什么落到具身智能

具身场景可能比软件 agent 更适合这套架构，因为生物就是这样演化出来的：运动控制太高频、太危险，等皮层「想清楚」早就摔倒了。

最贴切的隐喻是**膝跳反射**：叩击髌韧带 → 感受器 → 传入神经 → 脊髓灰质整合 → 传出神经 → 效应器 → 小腿抬起。全程**不走大脑**，毫秒级完成，且反射强度随牵张程度连续变化——它本身就是一条可校准的反射。

```
叩击(刺激) → 感受器 → 传入神经 ──┐
                                 ├→ 脊髓(灰质整合) → 传出神经 → 效应器(动作)
              大脑 ←── 上行通报(事后才知道) ─┘
```

机器人里的对应物：高频本体感觉 → 低层控制 → 动作原语；「大脑」（LLM/VLA）只在慢时间尺度上接管新任务，通常**事后**才被通报，而不是每一步都参与。

软件 agent 的决策频率是秒级，机器人控制环是 kHz 级。力矩、IMU、触觉阵列、关节编码器每秒涌进大量信号，而其中真正的「决策点」（要不要重新抓握、这个接触是预期内碰撞还是障碍）是**稀疏且可类型化**的。主流做法把原始信号序列一起塞进 VLA 模型（RT-2、π0）端到端学，问题不在于用了 VLA，而在于**把本该高频、局部的判断也交给了低频模型**。按时间尺度分层更合理：

| 层 | 频率 | 职责 | 本项目当前实现 |
|---|---|---|---|
| 脊髓 | 500 Hz – 1 kHz | 力矩/位置伺服、急停、硬护栏 | 500 Hz 伺服，确定性 PID |
| 小脑 | 50–100 Hz | 原语选择、风险判断、进展打分 | 规划中；决策头 50 Hz |
| 大脑 | 0.5–2 Hz | 「这个杯子打滑了，换目标还是调整姿势」 | 只留 escalate 接口，原型阶段不接 |

**一个具体例子**：触觉打滑检测。皮肤阵列 200 Hz 信号进脊髓做滤波与特征提取（接触力变化率的滑移模式），小脑的 Noul 输出「打滑概率 0.94」。0.94 是校准概率，不是触发频率——它意味着这类判断里约 94% 确实在打滑。真正把延迟压到毫秒级的是脊髓那条反射通路：判定为打滑后，抓握力重分配由 500 Hz 伺服环执行，皮层不参与；对比「拍图 + 大模型推理 500 ms」是量级差别。

这也改变了成本结构：高频决策被卸载后，大脑可以只配一个本地小模型。

### 「脊髓灰质」：数据总线

这是最容易做漏的一层，也是 ROS/ROS2 默认用法里最容易被绕过的部分。主张是**总线要分频、分级、事件溯源**：

1. **两类传入神经。** 本体感觉（关节角、力矩、IMU）走高频裸通道，脊髓自己消费；外源感觉（相机、深度、语言指令）低频进皮层。不要让所有信号共享一个 topic 队列——生物脊髓只做局部反射，视觉信号不会每毫秒打扰它。
2. **中间需要「脊髓灰质」：环形缓冲 + 特征压缩机。** 原始信号先进固定长度 ring buffer（如 2 s 滑窗），轻量编码器（甚至就是滑动统计量）把窗口压成结构化状态：`{接触状态, 滑移指数, 关节裕度, 近2s异常事件列表}`。**这才是喂给小脑 `state` 的东西**——小脑从不看原始波形。
3. **下行通路带「皮层门控」。** 生物里脊髓反射可被大脑抑制（踩到钉子还能走完那一步再叫）。每条下行命令标权重：脊髓级（急停）不可否决；小脑级（步态修正）可被大脑以低置信度为由否决；大脑级（重新规划）可被小脑以安全护栏否决。置信度在这里不只是路由信号，还扮演**神经调质**的角色。
4. **安全约束留在硬件层，别学习。** 工作空间限制、力矩上限、碰撞急停应是总线上的确定性旁路（hardwired interlock），任何学习组件都无权绕过。**脊髓不能删。** 同理，小脑 `Choice` 的候选集必须**先由代码做物理预过滤**（碰撞、关节限位、可达性），模型只在合法候选里挑——漏掉这一步，非自回归输出「零越界」的优势就只剩形式。
5. **事件溯源日志作为共同记忆。** 所有决策事件（state 快照 + 判断 + 完整概率分布 + 结果）落盘。这是可学习性的基础设施，也是唯一能复算对外数字的东西。

### 上线后怎么继续学

先划清范围：**阶段 1–2 是小脑学生的全量训练**（先 BC，再 RLCD 精调）。下面讲的是重量训练完成、部署之后，主干权重冻结时系统怎么继续进步——它不是初始训练方案，原型阶段也不启用。

生物的答案是：可塑性是局部的、受门控的、以记忆回放为载体的。

1. **小脑的学习 = 大脑裁决的蒸馏**（设计目标，尚未验证）。每次低置信度升级，大脑给出最终决策——这就是一个免费的标注样本 `(state, 大脑的选择)`。积累后按类 RLCD 目标微调 adapter（主干冻结）。**预期**效果是升级率随时间下降，小脑把大脑的判断内化成反射。这与生物小脑的监督学习（爬行纤维教学信号）对应。
2. **大脑的学习 = 小脑失败案例的回放。** 从事件日志筛两类高价值样本：小脑**高置信度但结果失败**的（过自信盲区）、小脑低置信度升级后**大脑也答错**的（真正的 OOD）。大脑因此在学的是**仲裁能力**。学习载体取决于大脑形态：原型阶段记进上下文记忆，真接 LLM 时再定是检索还是 adapter。
3. **用世界模型离线演练，而不是真机试错。** 在 MuJoCo 里跑小脑策略 + 简单大脑，用域随机化生成 `(state, decision, outcome)` 三元组，离线 RL 或校准回归更新 adapter。sim2real gap 由「低置信度升级」兜底——**不自信的反射天然保守**，这是设计预期，要靠阶段 4 的真机数据检验。
4. **学习要门控：不是每个错误都更新。** 对应生物可塑性受神经调质门控：只有**意外性**（prediction error）足够大且**事件重要性**（跌倒风险、任务失败）足够高时才触发写入，否则系统在噪声里漂移。工程上：事件日志 → 惊讶度打分 → 只把 top-k 意外事件送进学习管线。无差别的梯度更新会让系统平庸化。

四件事接起来：大脑教小脑（蒸馏仲裁）→ 小脑给大脑减负（卸载反射）→ 总线给两者提供共同语言（类型化状态）→ 事件日志让双方各自从对方的成功与失败中学习。

比端到端大模型路线慢热，但每一步都**可审计、可校准、可安全验证**。

## 参照实现：软件 agent 侧有人走通了前半段

两个开源复现把官方 Jev 的黑箱摊开了，各自验证了这套架构的一半。本项目的做法是拆开两边各取一半。**两者都没有在机器人上跑过。**

### NanoJev：验证了「问题设定」与「代码拥有工作流」

**NanoJev**（MIT，权重与数据全开源）是交付较完整的公开 Jev 复现之一——模型 + 数据集 + 训练管线 + 持久推理服务 + 可交互演示。

```
state + question + candidates
        │
        ▼
   Qwen3-0.6B 骨干        ← 单次前向，零输出 token 解码
        │                    多个 state/question/候选路径同批并行
        ▼
   共享决策头
     · Choice：集合注意力 + softmax → 2–255 个候选的分布
     · Boolean：sigmoid → 命题成立概率
     · Score：2–10 个有序等级的分布 + 概率加权期望
        ▼
   每个候选：类型化值 + 归一化概率
```

- 骨干 **Qwen3-0.6B**。项目自报的实测例子是 6 个状态、18 个问题、44 条候选路径在**一次前向**中全部解算。
- Choice 候选集动态（2–255），共享评分头 + 集合注意力并行打分后 softmax；Boolean 走 sigmoid；Score 输出等级分布与期望。
- 没有「投影到词表再逐 token 解码」这一步，输出直接是序列化概率张量，因此**排除的是 schema 越界**，不是所有解析错误。
- 单 checkpoint 跨 4 个游戏任务复用；FP32 权重常驻约 2.4 GB（这是推理显存，不是训练峰值）。

**最值得借的是它的系统哲学：代码拥有工作流。** 模型只做模糊的语义判断层，记忆、规划、安全约束全在确定性代码里：

| 任务 | 代码负责 | 模型负责 | 项目自报结果 |
|---|---|---|---|
| 50×50 迷宫 | 记撞墙历史、探索未走过的边、沿已验证路径回溯重定位 | 只判断四个局部方向的安全性 | 225 次行动到达终点；对照原版 Jev API 需 2738 次 |
| 贪吃蛇 | 常规规划器过滤立即碰撞动作、找出通往食物的静态路径 | 只在幸存动作之间打破平局 | 256 步回合内吃到 27 个食物仍存活 |

这正是本文「脊髓不能删」的独立验证：**模型是模糊判断层，不是整个程序。** 配套 JevHarness 让 LLM 自动编写任务专用的决策 harness。

### Laya：验证了「训练方法」与「安全出口」

**Laya**（ModernBERT-large 双向编码器路线，约 421M）走的是不同的架构赌注，自报了更好的校准指标。对本项目真正有价值的是两点：

- **RLCD 闭式更新**：不需要 PPO 的在线采样，按 `π* ∝ π_ref · exp(r/β)` 做指数倾斜迭代。对机器人这种「数据贵且离线」的样本友好。
- **act-or-escalate 头**：一个专门的「该自己拍板还是上报」的校准二值头，和「脊髓搞不定才上报」的逻辑对应。

### 借什么，不借什么

| 来源 | 借 | 不借 | 理由 |
|---|---|---|---|
| **Laya** | RLCD 闭式更新；act-or-escalate 头 | ModernBERT 文本骨干 | 文本编码器吃不了关节角、IMU、深度图 |
| **NanoJev** | 环境闭环的序贯决策设定；类型化决策头；代码拥有工作流 | 0.6B 解码器骨干 | 要在机载计算（Orin 级）跑到 50–100 Hz，0.6B 太重 |

所以本项目的**小脑是自己训练的小模型**，不是调用官方 Jev API：本体感觉小编码器（MLP / 1D-conv，目标 10–50M）+ 原语 Choice 头 + act-or-escalate 头，单次前向输出动作分布与 escalate 概率。官方 Jev 70–500 ms 的延迟进不了这个控制环，它在本项目里只作为设计参照；真要用，位置在大脑层。

> 关键设计：**把动作空间离散成「原语 / 技能」而不是电机力矩。** 这和反射的层级一致——小脑选的也是「伸腿」这个模式，不是逐个肌肉纤维。Jev 的 candidate-actions 设计在这里天然契合。

在具身形态里，上面第 2 条说的「置信度低于 τ 就升级」由 **act-or-escalate 头**实现：它和原语选择头一起训练，而不是事后给 Choice 的 softmax 套一个阈值。这样「该不该出手」和「出手选哪个」是两个独立的校准问题，逃避不会和动作挤在同一个分布里竞争。

### 与官方 Jev 的对应

| 维度 | 官方 Jev | NanoJev | Laya |
|---|---|---|---|
| 骨干 | 未公开 | Qwen3-0.6B | ModernBERT-large（约 421M） |
| 输出原语 | Choice / Score / Noul | Choice / Boolean / Score | 分类 + 校准 + act-or-escalate |
| 训练方法 | RLCD | 决策头监督训练 | RLCD 闭式 |
| 任务范围 | 通用类型化决策 API | 窄域游戏 | 窄域分类 |

### 边界

- **具身侧没人走通过。** Laya 和 NanoJev 的数字都来自软件环境；据我们检索，公开材料里没有把 RLCD 决策头放到机械臂上的工作。前两个月连仿真都调不顺是正常的。
- **别把脊髓做成端到端大策略。** 那样它就成了一个小 VLA，失去「快、可校准、可接管」的意义。它的价值在于**窄而确定**——当前只负责 4 个命名原语的选择和反射，不试图理解任务。
- NanoJev 的训练目标集中在游戏等窄任务，**不能外推为通用决策能力**；它证明的是「类型化决策头这个架构能跑闭环」，不是「拿来做机器人就行」。

## 现在做到哪一步（实测）

以下数字都来自本仓库的脚本，可按 [PLAN.md](PLAN.md) 第三、四节的口径复算。样本量普遍是 n=20 或 n=6，够用来找断崖和杠杆，**不够当成功率发表**。

### 本体：资产比看上去的更不理想

SO-ARM100 的 MJCF 取自 `ros2_so_arm`（Menagerie 风格，带碰撞网格与执行器），连杆惯量已与设计者 `Simulation/SO100/so100.urdf` 逐项核对一致。但三处实测偏离值得记下：

| 项 | 模型原值 | 实测/规格 | 处理 |
|---|---|---|---|
| 关节力矩上限 | ±3.5 N·m | Feetech STS3215 7.4V 堵转 **≈1.86 N·m** | `forcerange` 收到 ±1.86 |
| 舵机质量 | 6 个 `*_Motor` 网格 `density=0` | 单只 55±1 g，共 **0.33 kg** | 每个运动关节焊一个 55 g 子体 |
| 反射惯量 / 摩擦 | armature 0.1、未设阻尼 | 设计者参数 0.028 / 0.052 / 0.60 | 换用上游值 |

代价立刻可见：同一 kp=50 的位置环，稳态跟踪误差从 0.0141 rad 变成 0.0224 rad。臂重了约 45%、舵机上限砍半，**阶段 1a 的抓取力必须按 ±1.86 N·m 设计**。这些修正同时在本机 mujoco 3.16 与 3.3.4 下验证过，集群计算节点（osmesa、无 GPU）上资产级静态物理量一致；整段接触抓放的版本差异见「还没解决」。

### 工作空间：抓取比「能碰到」小得多

腕部朝向自由时的极限扫掠半径能到 0.43 m，但抓取要求夹爪朝下，可用空间小得多：正前方半径 **0.16–0.35 m**，腕高上限约 **0.20 m**。所以 `R_REACH = 0.32`。

「不可达」分支要放在物理上真够不着的地方，分两半：**太远** `r ≥ 0.42`（实测 0/6）和**太近** `r ≤ 0.14`（断崖在 0.14 与 0.15 之间：0.15 是 6/6 能放下，0.14 是 0/6）。填两半是为了防止策略把「远」当成 escalate 的代理特征。

### 夹爪：几条反直觉的实测结论

读 mesh 顶点（不是 AABB 角，AABB 会把指尖算到 110 mm 外）得到的：

- 接近轴是 wrist_2 局部 **−y**，闭合方向是 **x**；`q = −0.22` 是**闭合**端、`+2.0` 全开，和直觉相反。
- 捏合通道在腕前 **60–100 mm**，且两颚在 ~40 mm 处互相接触。于是 3 cm 高的方块平放在桌上时，捏合面永远在方块上方——**物理上捏不到**。目标物已改成 3×3×6 cm 立块。
- 夹爪**不对称**，通道中心不在接近轴上；直上直下会顶倒方块（实测滑移 45–55 mm）。补偿量 `depth ≈ 0.085–0.095 m`、`lateral ≈ −0.035–−0.025 m`。
- 通道中心随开度移动，**单个固定偏置不可能同时最优**，盆地只有约 10 mm 宽。所以专家轨迹不是每条都成功——**每条决策样本必须带轨迹 0/1 结果**，不能只信专家的意图标签。

### 真正的杠杆是感知通道，不是机械

同一套脚本序列、同一标定，在 20 个随机可达点位上：

| 目标位姿来源 | 成功率 | 失败构成 |
|---|---|---|
| 真值位姿（仅诊断，不进入观测） | 17/20 | 撞桌 1、堵转 1、滑落 1 |
| 单次含噪检测（σ=10 mm/轴） | **12/20** | 撞桌 4、滑落 2、堵转 1、超时 1 |
| 悬停平均 20 帧（= `对准`，部署配置） | 17/20 | 撞桌 1、堵转 1、滑落 1 |
| 悬停平均 60 帧 | **19/20** | 堵转 1 |

原因：单次检测的 3D 误差均值 16.8 mm（σ=10 mm/轴，3D 误差 ≈ √3·σ），已经是夹爪约 10 mm 横向容错的 1.5 倍以上，20 次里丢 8 次；20 帧平均把误差压到 3.1 mm，成功率回到真值水平（17/20），60 帧到 2.0 mm / 19/20。真值也只有 17/20——剩下 3 次是捏合盆地和夹持滑落，不是感知。所以「对准」不是可选步骤，而是这台臂在真实定位精度下能抓的前提。顺带一个教训：先取一帧再做 EMA 平滑完全无效——目标点只由开头那一帧决定，必须**先采 K 帧再决策**。本表是 2026-10-27 用当前代码、每个位点独立采样检测噪声复测的；旧表的「单次 2/20」把同一个噪声实现重复了 20 次，已废弃。视频与逐 episode 日志见 `scripts/render_pose_sources.py` / `data/demo/pose_sources.json`。

**过程数据（逐 tick）**：sweep 同时写 `data/demo/traces.jsonl`，每个 50 Hz 决策 tick 一行，含
`q / q_target / qvel / tau / ee / ee_axis / block / block_vel / grip / table_force / trips / phase`。
同一试次 02/20（r=0.281 m）：
单次检测在 **t=5.12 s** 方块跌破 `hold_z` 时夹爪仍停在 **0.286 rad**，方块在颚间下滑 **14.2 mm**，
t=6.16 s 判 `dropped`；20 帧平均的夹爪停在 **0.247 rad**，方块只下沉 **1.6 mm**、稳定运到释放点，
t=8.36 s 释放、t=8.96 s `placed`——但方块最高只到 0.0413 m，没过 `hold_z` 0.045，所以 +1 夹持奖励不触发。

单试次诊断：`scripts/plot_trace.py --source single --trial 2`（加 `--csv`
导出该试次的逐 tick 平表）；近景 0.5× 对照：`scripts/render_trace_clip.py`。

同一批实验还排除了三个直觉上的杠杆：换目标物形状（更高 / 更细 / 圆柱全部 0/20）、放宽撞桌力阈值（3→8→15 N，成功率不变，只是把失败**改名**成 arm_straining）、压低带载高度（0.15→0.12 m 直接 0/20，重力矩吃掉力矩余量，臂伸得越低越糟）。

### 总线与观测契约

`test/test_bus.py` 不碰 MuJoCo，用合成帧验证整条观测通路，几秒跑完：

- 观测是固定的 **35 个 float、9 段**：`q / qvel / tau / ee_pos / ee_axis / obj_pos / obj_conf / joint_margin / grip_slip`。
- 环形缓冲 100 帧 × 20 ms = 2 s 滑窗。
- 感知模拟器：测试用比部署更严的压力参数（σ=20 mm/轴、漏检率 0.4）。清晰时平均 3D 误差 32 mm，遮挡时 σ 放大到 200 mm、误差升到 317 mm；400 个遮挡 tick 里 153 个直接报「未检测到」，平均置信度从 0.90 降到 0.20。部署配置的清晰档是 σ=10 mm/轴，对应 3D 误差约 17 mm。
- `grip_slip` 按 100 mm/s 饱和：静止和刚性搬运读 0，20 mm/s 蠕动读 0.2。
- 事件日志 425 B/行，一百万条决策约 0.43 GB。
- 关键断言是**观测通路上没有任何东西读真值**——这条契约由测试守着，不靠自觉。

### 还没解决

**夹持不刚性。** LIFT 报到位时方块在下颚里下滑约 16 mm，静置 0.6 s 后还会掉。1.86 N·m 的夹紧力夹 30 g 方块不是刚性夹持，所以「夹持稳定并保持 T 秒」这项 +1 奖励在放置成功的轨迹里也常常不触发。没有把判据调松去凑数——这恰好是 `Score`（1–5 档）该表达的东西：**能移送 ≠ 夹得稳**。

**mujoco 版本割裂在整段抓放上没解决。** 资产级测试（加载、限位、静态力矩、渲染）两版一致，但同一段脚本在 3.16 下真值位姿 17/20，在 3.3.4 下只有 4/20：闭合夹爪时方块被推出，触发 `arm_straining`。集群上限被 glibc 2.17 钉在 3.3.4，接触丰富的训练数据会因此与本机演示不一致；阶段 1c 采样前必须定位或固定版本。

**限位仍是占位值。** 对照设计者 URDF 逐关节核对后有两处对不上：`elbow_flex` 比官方行程多 0.18 rad，`wrist_roll` 少 1.28 rad。两者都只记不改——改宽会允许真机做不到的姿态，改窄可能禁掉真机能做的，等阶段 4 实测一起定。

## 快速开始

需要 MuJoCo 与 numpy；本机用 `uv` 建虚拟环境：

```bash
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r test/requirements.txt
```

然后按想验证的层次跑对应测试：

```bash
.venv/bin/python test/test_mujoco.py             # 环境是否可用
.venv/bin/python test/test_so_arm100.py          # 资产加载 / 步进 / 渲染
.venv/bin/python test/test_spine.py --envelope   # 夹爪朝下时的可达格点图
.venv/bin/python test/test_spine.py --rate 20    # 20 个点位的抓放成功率
.venv/bin/python test/test_bus.py                # 总线与感知模拟器
```

渲染后端是在**子进程**里逐个探测的——同一进程内改 `MUJOCO_GL` 不生效。版本预检（集群上限 mujoco 3.3.4）与环境细节在两个环境里各跑一遍即可：

```bash
.venv334/bin/python test/test_so_arm100.py --skip-render
.venv334/bin/python test/test_spine.py --profile
```
